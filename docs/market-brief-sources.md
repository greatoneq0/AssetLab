구현은 공개 RSS로 발견한 언론사 **본문**에서 같은 날의 `N일 오전 6시/7시 ... 서울 외환시장 ... 원·달러 환율 ... X원에 거래를 마감`처럼 날짜·시각·가격과 실제 완료 마감이 한 절에 명시된 문장만 받습니다. 주간/야간의 여러 마감 가격이 한 문장에 섞이거나 전망·예상 표현이면 거부합니다. 기사 발행일, 예상 마감시각, 현재시각을 대조합니다. 숫자 충돌, 오래된 보도, 주간/역외 시세, 제목만 있는 보도는 채택하지 않습니다. 현재의 제도 시작 이전 및 연말 특별 마감은 별도 검증 없이는 조회 불가입니다.

[서울외국환중개 표](https://www.smbs.biz/ExRate/StdExRate.jsp)에 `06:00 종가`가 검색 색인에 보이지만 원문 조회가 502/프록시 403으로 실패했습니다. 표의 날짜 열이 거래일인지 공시일인지 검증하지 못했으므로 임의 파서를 배포하지 않았습니다. 기사 본문을 얻지 못하거나 엄격한 문장 조건이 맞지 않으면 **서울 야간 종가 확인 불가**로 표시합니다. Yahoo KRW=X, 15:30 가격, MAR, NDF로 폴백하지 않습니다. 공개 RSS의 보도 범위 때문에 매일 값이 확보된다는 보장은 없습니다.

## 검증

`python -m pytest -q`는 저장된/합성 응답을 사용하며 실제 텔레그램을 호출하지 않습니다. 기사 파서는 공개된 실제 마감 보도 문장도 테스트합니다. 본 작업 환경의 외부 사이트 직접 연결은 프록시 403으로 차단되어 **실제 최신 FX/RSS 수집 성공은 검증되지 않았습니다**. `python tools/market_brief.py --dry-run`은 발송 없이 실제 조회 결과 또는 조회 불가를 출력합니다. 어떤 secret이나 지속 인증 설정도 추가하지 않습니다.

## 2026-10-16 뉴스·08시 예약 수정

기존 88개 회귀 테스트를 먼저 통과시켰다. 이전 설명의 **한 문장에서 원인까지

- 기존 직접 원인 발췌는 유지한다. 별도 경로로 기사 본문의 날짜, 개별 종목,

  동일한 종가를 우연히 언급한 전망·과거·장중 문장은 제외한다.
- `이날`의 날짜는 앞의 최대 다섯 문장 안에 있는 같은 시장의 명시 날짜만 받는다.
  직전 문장이 같은 시장의 완료 마감이면 그 다음 지수 문장도 같은 범위에서 확인한다. 중간에 다른 날짜가 나오면 이어 붙이지 않는다. 여러 지수가 있는 문장은
  종목 경계별로 숫자를 검증한다. 미국 기사에서 흔한 `5만2177.69`도 지원한다.
- 이 경로는 원인을 추론하지 않는다. **마감 동향**과 **주요 보도(기사 제목)**를
  분리해 표시한다. 제목만으로는 수락하지 않으며 반드시 본문 마감 검증이 선행한다.
- HTTP URL/상태/content-type/charset/bytes, RSS 전체·날짜 통과 항목 수,
  본문 글자 수, 종목별 거부 사유, 총 채택 수를 기록한다. HTTP 실패,
  본문/디코딩 실패, 날짜 불일치, 종가/등락률/방향 불일치를 구분한다.
  bytes를 BeautifulSoup의 자동 추측 디코더에 바로 전달하지 않고 UTF-8,
  CP949를 엄격하게 해독한다. 복구 불가능한 바이트/대체 문자는 제외한다.
  기존 실행의 경고 열 개가 어떤 URL에서 발생했는지는 과거 로그로 단정할 수 없다.

### 오전 8시

cron을 `0 23 * * *` (08:00 KST)로 변경했다. 이는 **실행 예약**이며
준비·조회·전송 시간이 더해지므로 08:00 도착 보장이 아니다. GitHub는 정시의
부하로 지연 및 대기 작업 누락이 가능하고 기본 브랜치에서만 예약이 작동한다고
[공식 문서](https://docs.github.com/en/actions/reference/workflows-and-actions/events-that-trigger-workflows#schedule)에 명시한다.
따라서 이 PR이 병합되기 전 main 예약은 바뀌지 않는다.

기존 인프라에서는 pip 캐시로 준비 시간을 줄이고, 발송 작업을 기본 브랜치로
제한하며 concurrency로 수동·예약 실행의 겹침을 막는다. KST 날짜별 정확한 cache
key로 발송 시도 전에 claim을 저장하고 다시 읽어 확인한다. 이미 claim이 있으면
발송하지 않는다. 저장이 불확실하면 발송하지 않는다. 전송 결과가 불확실하거나
발송 전 오류가 나도 당일 자동 재발송은 하지 않는 보수적 방식이다. GitHub cache는
퇴거/삭제될 수 있으므로 영구적인 exactly-once 보장은 아니다. 캐시를 삭제해 재시도할
때는 실제 수신 여부를 사람이 먼저 확인해야 한다. 추가 cron/반복 발송은 넣지 않았다.

선택지: 정시 부하를 피한 07:45~07:50 준비 후 08:00까지 기다리는 단일 예약은
지연 가능성을 줄일 수 있지만 runner 시작 자체가 늦으면 해결되지 않는다.
이번 요청의 08:00 cron은 유지했으며 이 대안은 적용하지 않았다.
보다 안정적인 08시 목표에는 상시 실행 호스트의 cron/systemd timer 등 독립
스케줄러와 사전 수집이 필요하다. 사용자가 호스트를 선택·상시 가동하고 기존
Telegram 자격증명을 안전하게 전달하며 GitHub 발송 예약을 비활성화해야 한다.
그 경우에도 네트워크와 Telegram 전달 자체에 대한 정확한 도착 SLA는 별개다.
외부 서비스, 자격증명, 유료 가입은 추가하지 않았다.

## 후속: 본문 뉴스 범위와 발송 결과 구분

아래 내용은 앞의 제목 중심 출력 및 cache claim 설명을 대체한다.

### 키 없는 추가 출처

[연합인포맥스 공식 RSS 목록](https://news.einfomax.co.kr/rssIndex.html)에서 확인한
국제뉴스 `S1N23.xml`, 해외주식 `S1N21.xml`, 채권/외환 `S1N16.xml`, 칼럼/이슈
`S1N9.xml`을 추가했다. 칼럼/이슈에는 뉴욕유가·뉴욕마켓워치 등 정기 마감 보도가
포함된다. 특정 날짜 기사 URL은 **운영 수집 코드에 넣지 않는다**. 고정 URL 세 개는
사용자가 지목한 10/15 회귀 재현용 검사에만 있고, 실제 수집은 매번 공식 피드에서
발견한 링크를 사용한다. 새 API 키/로그인/유료 모델은 없다.

이 출처의 RSS는 발행시각을 `YYYY-MM-DD HH:MM:SS` KST로 제공한다. 이 형식의
시간대 부여는 연합인포맥스 이름과 정확한 호스트가 모두 일치할 때만 허용한다.
다른 출처의 시간대 누락은 계속 거부한다. 기사 본문 컨테이너
`#article-view-content-div`만 읽으며 페이지 전체/메뉴를 본문으로 사용하지 않는다.

표시는 세 종류를 구분한다.
- 직접 원인 문장: 종목·날짜·방향·완료 마감을 엄격히 확인한 원문 발췌.
- 주요 보도(본문): 검증된 마감 기사의 도입부에서 짧은 경제/시장 설명을 발췌.
  제목만 있는 경우 성공으로 집계하지 않는다. 직접 인과로 합성하지 않는다.
- 본문 요약 미확보: 시세 또는 기사 제목만 표시하며 본문 뉴스 확보로 집계하지 않는다.

원자재의 보수적인 Yahoo 일봉 시세 날짜가 10/14이고 마감 기사가 10/15 세션이면
시세를 10/15로 덮어쓰지 않는다. 별도 경로에서 발행시각·명시 사건 날짜·완료 마감과
본문을 확인하고 **기사 세션 10/15 · 상단 시세와 별도 세션**으로 표시한다.
오래된 기사·전망·장중 설명은 해당 세션 마감으로 채택하지 않는다.

### 발송 결과 ledger (기존 cache claim 대체)

기존 cache claim은 성공 여부와 무관하게 당일 전체를 막았다. 이를 제거하고
GitHub Actions artifact에 attempt별 상태를 보존한다. 별도 credentials 없이
기본 `github.token`으로 artifact 이름을 읽으며 `actions: read`만 필요하다.

1. 메시지 생성과 설정 검증 실패는 발송 시작으로 기록하지 않는다.
2. 전송 직전에 `started` artifact를 저장한다. 저장 실패 시 전송하지 않는다.
3. Telegram이 성공을 확인하면 `sent`, 명시적으로 거절하면 `rejected`를 저장한다.
4. timeout/연결 종료/해석 불가능 응답은 `unknown`이다. `started`만 남은 경우도
   수신 불확실로 취급한다. **실패/불확실을 완료로 기록하지 않는다.**
5. 동일 KST 날짜의 `sent`는 기본적으로 건너뛰고, `rejected`만 있으면 재시도 가능하다.
   `unknown`은 수신 확인 전 자동 재시도를 막는다. 실행 전체 concurrency는 유지한다.
6. 수동 실행 기본값은 `preview`이며 발송하지 않는다. `send`로 명시한 수동 시험은
   PR 브랜치에서도 가능하다. 기존 수신을 확인하고 추가 시험을 승인한 경우에만
   `approved_retry=true`로 성공/불확실 기록의 차단을 명시적으로 해제할 수 있다.

실제 발송 없이 모의 전송/HTTP 응답으로 성공, 명시적 거절, timeout, 알 수 없는
응답, 다른 날짜, 여러 artifact 페이지, API 실패, 승인된 수동 시험과 설정 누락을
검증한다. 이 작업에서 send/approved_retry workflow dispatch는 수행하지 않았다.
Artifact 삭제/만료, 외부에서 직접 실행한 Telegram 발송은 ledger로 보장할 수 없다.
30일 보존은 당일 중복 방지용이며 영구 exactly-once 전달을 약속하지 않는다.
